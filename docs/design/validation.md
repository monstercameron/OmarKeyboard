# Omar Keyboard UX review

The costs that matter most are typing into the wrong window, moving a tile by accident, and discovering a missing key in the middle of work. The design gives ordinary typing and window focus immediate recovery paths. The hold timing and reach dimensions remain hypotheses until someone uses a physical sample.

## Review decisions

| Concern | Decision | How to check it |
| --- | --- | --- |
| 1. No function keys | Omar deliberately has no function keys. Digits, minus and equals type normally with Caps held. Applications whose function-key shortcuts matter must be rebound inside that application. | List the applications you use daily and rebind any shortcut that depends on a function key before relying on the board. |
| 2. Right Ctrl | The right 1.75u key sends HID Right Control. Both Super keys stay Super under Fn. | Check make and release on R5/C6 with an event viewer. In an editor try Ctrl + Left, Ctrl + Shift + Right and ordinary typing after release. |
| 3. Stock compatibility | Desks, movement, window cycling, clipboard, menu and app grid emit stock Omarchy input. Super + Tab keeps its workspace action. | Test on an unmodified v4.5.0 install before loading the optional bindings. |
| 4. Accidental Focus or Swap | Both work only while held. If both are down, Focus takes priority. A brief touch cannot redirect the next arrow. | Brush each key, then arrow through a line in an editor. Repeat with the backlight off and while holding Shift to select text. |
| 5. Stale transfer | The only destinations are the five labeled desks. The three-second timer and local lights clear together. Arrow, typing, Focus, Swap and dial presses cancel. Modifiers, holding Caps and dial or roller turns do not cancel. Last Desk cancels and visits history. | Check just before and at expiry, Esc, repeated arm, replacement arm, ordinary digit, Last Desk, arrow, sleep/wake, Shift then Desk 3 (completes) and a volume turn mid-transfer (keeps the transfer). The stock move-to-monitor command has separate follow behavior. |
| 6. Window cycling and reach | Next Window taps forward, Shift reverses, Fn recalls the previous distinct window on this desk. Its cap center is about 12 mm closer to the typing area. The 2.25u cap needs a 2u stabilizer and a custom cap. Right Super remains immediate. | With three windows, distinguish reverse cycling from returning to the editor used last. Compare thumb reach across hand sizes. Trial tap-for-Next/hold-for-Super only if reach still fails. |
| 7. Navigation cluster | Fn + arrows give Home/End and PgUp/PgDn. Fn + Delete gives Insert. Delete stays above Backspace. | Select to end of line with Shift + Fn + Right. Page through a terminal pager and toggle overwrite in a supporting editor. |
| 8. Pinky misses at the rails | Half-unit separation on each side. Menu and Focus have tactile bars. The right rail stays because the bottom-right corner is where a pinky can hold Focus while the other fingers use the arrows. | Alternate Caps/Menu and Ctrl/Files without looking. Record wrong launches. Repeat around the arrow cluster, holding Focus with the pinky. |
| 9. Dials | Volume press mutes speakers, Shift + Menu opens Apps. Brightness stays on the right dial. Fn + turn resizes a split and press selects Layout. | Test laptop panel and external DDC/CI display separately. Turn the right dial fast and count accidental Lock presses. |
| 10. Pins | 92 switch contacts fit 8 × 12. Three encoders and a light chain bring the total to 27 GPIO. | Cross-check the wiring and scan all positions and encoder directions before populating lights. |
| 11. Roller and pointer | Normal wheel follows desktop routing. Fn + roller pages in the focused app. The tread is 42 mm wide. | Park the pointer in pane A, keyboard-focus pane B and roll with and without Fn. Repeat across two monitors and try a supported bearing/axle mockup. |
| 12. Five desks and state lights | Five physical targets, five-desk traversal by default, explicit stock-profile opt-out. Desk and microphone indicators accept only fresh host reports. | Change desk or microphone from another device, move between monitors, disconnect the host bridge and wake the board. Unknown state should clear within three seconds. |

## Before committing the plate

1. **Paper fit.** Use the [full-size template](../prototype/OMAR-KEYBOARD-PROTOTYPE.html). Check both 100 mm scale marks. The 404.8 mm span is close to a full-size board’s width, so also measure the reach from the home row to the mouse. Ask at least one newcomer and one experienced tiling user to find Next Window, send a browser to Desk 3, then continue working in the editor. Record first key, wrong transfers, hand lift and gaze shifts. Compare both Super positions.
2. **Firmware pilot.** Exercise a real QMK board with the [pilot instructions](../build/pilot.md). Check that left and right Ctrl, Shift and Super remain independently usable, modifiers do not cancel a pending transfer and a held direction never sticks. Disconnect and reconnect after arming Send & Stay.
3. **Live Omarchy.** Repeat the review’s tests with three windows on one desk, a second monitor and a different window under the pointer. Exercise copy/paste in GUI and terminal, keyboard screenshot selection, mic changes and a supported DDC display. Cold-boot on wired USB. Exercise letters, punctuation, digits and required modifiers in the actual unlock flow.
4. **Roller sample.** Record closed current for A and B separately (1–10 mA), 30 host events per revolution at slow and fast speeds in both directions, and the response at reversals. Turn the tread under center and end loads. Record minimum hood/plate gaps, sleeve grip, end float and shaft engagement. Demonstrate removal and refit of R04 with the coupled rotor and lug-soldered card, including wire and driver clearance. [Fixture and acceptance criteria](../../hardware/assembly-design-specification.md)

## What has been verified

The browser check covers the 92 switch positions, Fn and Super legends, hold-only Focus/Swap, transfer outcomes, cancellation, expiry, reverse cycling, last-window recall, split resizing, focused paging, mute, capture and Guide. The C harness, host test and browser check were updated for the current layout and transfer rules. The print drawing renders on two landscape sheets at a 19.05 mm key pitch. No physical reach time or error rate has been measured. Browser results establish the interaction rules. The acceptance tests above establish whether the finished hardware and OS deliver them.
