# Keyboard market and platform conventions

**US market · November 17, 2026 · 12 external keyboard families**

The **System76 Launch** illustrates the thumb-layer approach explored in Omar-Keyboard’s first layout. It keeps familiar staggered letter rows and splits the spacebar into independently mappable keys. One thumb can type Space while the other holds a layer. The **Lofree Flow84** is a compact board named in Omarchy’s own guide, and the **ZSA Voyager** shows what happens when a designer commits to thumb keys and layers across the whole keyboard. ## What changes between platforms

**Which modifier sits under the thumb?** On a conventional US Windows keyboard, the left-hand order approaching Space is Ctrl, Windows, Alt, Space. On a Mac, Option and Command approach Space in that order, putting Command under the thumb. On Omarchy, the Windows-logo or Command key normally acts as Super. A Mac user and a Windows user can therefore recognize the same desktop action and reach for different physical positions. ChromeOS maps a Windows keyboard’s Windows key to Search or Launcher. For Omar, “Super” is a clearer primary legend than an OS logo. [Omarchy’s platform guide](https://omarchy.org/manual/coming-from-mac-or-windows/) · [ChromeOS keyboard guide](https://support.google.com/chromebook/answer/1047364?hl=en) · [Apple keyboard layouts](https://support.apple.com/en-us/102743)

**Where do the arrows live?** A full-size board gives arrows and navigation a separate block. A tenkeyless board removes the number pad. A typical 75% board brings arrows and navigation closer to the letter keys and retains the function row. On compact boards such as the US HHKB and Wooting 60HE v2, arrows are available through a layer. If Right already takes Fn plus another key, swapping a window with Super + Shift + Right may require four physical keys. A held WM key mapped directly to Super + Right can bring that back to three when Shift is added. [Keychron V1 Max](https://www.keychron.com/products/keychron-v1-max-qmk-via-wireless-custom-mechanical-keyboard) · [Wooting layer guide](https://wooting.io/quickstart/keyboard/wooting-60he-v2/module) · [Omarchy navigation](https://omarchy.org/manual/navigation/)

**What persists after you switch?** A host selector chooses the computer receiving keystrokes. An OS selector chooses the mapping for that computer. A momentary layer changes what keys send while held. Logitech’s Easy-Switch, Keychron’s Mac/Windows toggle, and System76’s Fn layer illustrate the difference. Omar’s Caps/Fn key is a momentary layer. A workspace layout in Omarchy is a fourth kind of state, managed by the desktop itself. [Logitech host switching](https://support.logi.com/hc/en-us/articles/13750828691991-Getting-Started-MX-Keys-S) · [System76 layers](https://system76.com/support/launch-keyboard/) · [Omarchy workspaces](https://omarchy.org/manual/navigation/)

**Which variations affect international users?** ANSI, ISO, and JIS are physical arrangements. A Windows/Mac switch changes key behavior but cannot change the Enter shape or add missing physical keys. Omarchy binds workspace numbers and certain resize actions by physical position, so an exported keymap and printed legends need to agree on which positions send those commands. [Apple layout identification](https://support.apple.com/en-us/102743) · [Omarchy’s physical bindings](https://github.com/omacom/omarchy/blob/v4.5.0/default/hypr/bindings/tiling.lua)

## What carried into revision 3

The market study explored a 75% split-spacebar concept. Revision 3 keeps a single 6.25u Space, two thumb-reachable Super keys and physical arrows. It gives directional window actions their own hold keys. The [keymap](../design/keymap.md) describes that arrangement, and the [paper-fit trial](../design/validation.md) checks how its wider case affects mouse reach.
